# Запись аудио DictAI на Linux

Адаптер `lib/features/record/data/linux_audio_capture.dart` обслуживает запись
микрофона и совместную запись микрофона с системным звуком. Подключение к экранам
обычного и анонимного режимов выполняется в TASK-FE-001.23/.24. Эта инструкция
описывает требования адаптера, а не подтверждает готовность всего приложения.

## Требования окружения

- Linux desktop с доступным PulseAudio либо PipeWire с PulseAudio compatibility.
- `pactl` и `parec` в PATH процесса приложения. Для совместной записи также
  необходим `ffmpeg`. Приложение не устанавливает пакеты автоматически.
- Доступный микрофон и, для системного звука, monitor текущего default sink.
  Отдельный ALSA без PulseAudio API этим адаптером не поддерживается.
- Доступное временное хранилище. До завершения смешивания одновременно хранятся
  два исходника и итоговый WAV. Исходники не содержат пользовательских имён спикеров.

Проверить доступность можно командами `pactl list short sources`, `pactl info` и
`ffmpeg -version`. Не публикуйте вывод с частными именами устройств в задачах.
Зависимости и политика установки зависят от дистрибутива и владельца компьютера.

## Поведение адаптера

Микрофон выбирается явно либо берётся из Default Source. Monitor не предлагается
как микрофон. Для системного звука выбирается только `<Default Sink>.monitor`,
другой monitor не используется автоматически. Устройства фиксируются при старте.
Смена default sink во время записи не означает перенос уже начатого capture.

Процессы запускаются без shell, с отдельными аргументами и `LC_ALL=C` для разбора
метаданных pactl. Parec пишет PCM16, 16 kHz, mono RIFF WAV. Ошибки запуска,
раннее завершение, недоступный monitor и ошибка mixer являются явными ошибками.
Переход к mic-only требует нового явного выбора пользователя, скрытого fallback нет.

Отмена подтверждения Stop сохраняет активную запись. Подтверждение посылает SIGTERM,
ожидает exit и закрытие stdout/stderr. При таймауте используется SIGKILL, такой
результат не считается успешно завершённым WAV. После успешного завершения обоих
входов ffmpeg смешивает их до большей длительности, сохраняя PCM16/16 kHz/mono.
Пауза не поддерживается и должна быть скрыта в UI. SIGSTOP не применяется.

Каждый исходник и итоговый файл проверяются общим WavValidator. Частичный mixer
output не публикуется, при неудаче удаляется только этот owned partial. Исходные
файлы сохраняются для диагностики/восстановления. После успешного микса промежуточные
входы удаляются, итоговый файл остаётся до передачи в durable upload journal.
Dispose останавливает и ожидает дочерние процессы, не запускает upload или mix.
Политику хранения исходников после ошибок и очистку сессии завершает интеграция
.23/.24/.34. Это не гарантия восстановления ещё не завершённого WAV после аварии ОС.

## Проверка

Из корня frontend с закреплённым Flutter SDK выполнить
`flutter test --no-pub test/features/record/linux_capture_test.dart`.
Тесты используют fake Process и настоящие небольшие синтетические WAV, проверяют
порядок остановки, финализацию, ошибки, таймауты и cleanup. Они не доказывают
совместимость libsndfile/parec, драйвера, реальную синхронизацию звука или сборку Linux.

Полный реальный smoke предусмотрен TASK-FE-001.37 после интеграции .23/.24/.49.
На Linux host отдельно проверить mic-only и combined, отмену и подтверждение Stop,
многократный старт, недоступное устройство, отключение источника, заполненный диск,
таймаут/ошибку ffmpeg и отсутствие оставшихся процессов после выхода.
Проверить оба источника на слух, WAV валидатором и duration, включая длинную запись.
Записать версии ОС/пакетов, команды и PASS/FAIL/NOT RUN без записей встреч и секретов.
На macOS реальный Linux capture и `flutter build linux` считаются NOT RUN.
